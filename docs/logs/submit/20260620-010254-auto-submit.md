## Commit Body

check-source-locks.mjs fails when the locked commit does not
exactly match the source repo's HEAD (strict equality). That is
the right behavior for "is this CI pinned to the right commit?"
but it does not surface gradual drift between commits: every
new commit to axiom-owned repos that consume sources.lock.json
silently pushes the lock out of date until somebody runs
source:check manually.

Add check-source-locks-age.mjs: a soft, advisory companion
script. For each source entry it counts the commits between
the locked sha and the current HEAD and the committer-time
delta, and emits a WARN if either exceeds a threshold
(defaults: 5 commits OR 7 days; both are configurable via
env AXI_SOURCE_LOCK_MAX_COMMITS / AXI_SOURCE_LOCK_MAX_DAYS).
Modes:
  - default (warn):    exit 1 on WARN, 0 on OK, prints to stderr
  - --strict:          exit 2 on WARN (for cron / scheduled CI)
  - --json:            machine-readable summary for dashboards

Three drift paths are covered: OK (locked == HEAD), real
drift (locked behind HEAD), and invalid sha (locked references
an object that does not exist in the source repo). The invalid
sha path was caught by a hand-faked lock entry during local
testing: the original logic fell through the age branches
because NaN>threshold is false and an empty lock time produced
daysBehind=0; the fixed script returns WARN with an explicit
reason in that case.

Wire the script into the repo:
  - pnpm source:age / pnpm source:age:strict scripts in
    app/package.json (does NOT enter governance:check; the
    strict equality check there remains the source of truth).
  - New "Source lock age advisory" step in
    .github/workflows/axi-ci.yml runs source:age after
    governance:check, wraps output in ::group:: / ::endgroup::
    and surfaces any non-zero exit via ::warning:: so the PR
    review sees the drift without failing the build.

Defaults were chosen to match the threshold the 2026-06-19
cross-repo self-consistency review identified as the point
where drift becomes a real problem (8-day silent drift was
the actual failure mode). Lowering the thresholds in the
future is a single env-var change; raising them is a code
change.

Confidence: high
Scope-risk: narrow
Directive: After this commit, every CI run on axi-docs
emits a Source lock age advisory block. Operators reviewing
a PR that touches sources.lock.json OR that touches a
source's repo will see the drift line; raising or
silencing the warning requires an explicit env-var override
or a code change to the thresholds, not a comment in
sources.lock.json. If the warning fires on the local dev
machine, run `pnpm --dir app source:age` to see the
detailed breakdown before deciding whether to bump the lock
or to leave it alone.
Tested: Local validation against four scenarios:

  (d) lock behind HEAD by 10 commits -> exit 1, WARN line
