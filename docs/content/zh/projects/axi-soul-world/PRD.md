# Axi Mood 记录模块产品需求文档（PRD）

> 状态：孵化中（PRD）  
> 版本：0.1  
> 更新日期：2026-08-22

> 归属说明：本文只定义 Axi Soul World 中的 Axi Mood 私密记录模块，不定义整个 Axi Soul World 的社交产品边界、总后台部署方式或未来 Web/宿主后台形态。总后台与多端承载以 [BACKEND_ARCHITECTURE_PLAN.md](./BACKEND_ARCHITECTURE_PLAN.md) 为准。

## 1. 决策摘要

**Axi Mood 是 Axi Soul World 中只属于一个人的、本地优先的自我心情保留地模块。**

它像一本可持续生长的私密日记，也借用朋友圈的时间流、图片卡片和“这一刻”表达方式；但它不是社交网络，不存在公开广场、关注关系、他人动态、点赞评论或默认上传。

当前界面中的“自留地”“自己”“设置”主要是为底部导航的视觉对称而保留，不能视为已经成立的产品分区。本 PRD 将它们重新定义为：

| 概念 | 产品定义 | 不应承担的含义 |
| --- | --- | --- |
| 自留地 | 产品整体的私密个人记录空间；也可作为日后“记录流”的名称 | 公共动态、他人内容、独立于“自己”的第二套数据 |
| 自己 | 个人档案与回顾视角；只有在拥有资料、时间线、统计或个性化能力时才保留为独立入口 | 与“自留地”重复展示同一批记录的第二个首页 |
| 设置 | 隐私、数据、外观和提醒等管理能力 | 仅为凑齐底部导航的内容页 |

在 MVP 中，所有内容均归属于当前设备上的用户；“私密”是系统默认，而不是发布时可选的可见性开关。

## 2. 背景与问题

个人的情绪、想法、待办、临时备忘、照片、打卡和文件常分散在社交平台、备忘录、任务清单与相册中。它们的记录方式不同，回看路径断裂，也容易因为社交产品的公开性而降低真实表达的意愿。

现有 Android 原型已经证明了本地心情记录、图片动态、相册、封面与按日期回看的基础体验；但它仍是简化版本：

- 动态、相册和个人时间线使用同一批本地记录；
- “自留地”和“自己”没有真实的数据或权限边界；
- “谁可以看／公开”只是界面文案，尚未保存为数据能力；
- 待办、备忘录、打卡、通用文件附件、统一检索、数据备份和应用级保护尚未形成产品能力。

本阶段的目标不是扩展成“另一个超级 App”，而是验证一个统一的私密记录核心能否承载这些自我材料，并保持低摩擦、可回看、可掌控。

## 3. 目标用户与核心价值

### 目标用户

以设备拥有者本人为唯一用户：希望持续记录生活与情绪，又不希望内容天然进入社交传播链路的人。

### 核心价值

1. **放心写下**：默认仅保存在自己的设备中，不需要先判断“能不能让别人看”。
2. **把碎片留在一起**：心情、文字、图片、待办、备忘和打卡都能成为同一段个人生活的组成部分。
3. **以后找得到**：按时间、类型、关键词、标签和附件回看，而不是让内容沉没在多个 App 中。
4. **数据由自己掌控**：查看、导出、删除与未来的备份必须由用户主动发起，不能把本地优先误写成云端依赖。

## 4. 产品原则

### 4.1 私密优先，而非“公开后再隐藏”

- 新建记录默认私密且仅本机可见。
- 正常记录、浏览、搜索和回顾流程不得上传内容或建立社交关系。
- 用户主动导出、分享或未来主动启用备份时，必须明确显示数据范围和目标。
- “仅存本机”不等于“已经安全加密”：应用锁、系统生物识别和加密备份属于后续必须验证的保护能力，不能提前宣称已具备。

### 4.2 一条个人时间线，多种记录形态

所有内容进入统一的个人时间轴，但保留各自的结构化字段：

| 记录类型 | 主要内容 | 后续结构化字段 |
| --- | --- | --- |
| 心情／日记 | 文字、心情、图片或视频 | 心情标签、地点（可选）、日期 |
| 备忘录 | 自由文本、灵感、片段 | 标题、标签、置顶 |
| 待办 | 要做的事 | 完成状态、截止时间、提醒、关联记录 |
| 打卡 | 重复或一次性的自我记录 | 习惯、频次、连续天数、备注 |
| 附件／文件 | 图片、音频、视频、文档等 | 文件类型、来源、预览、关联记录 |

“朋友圈感”只指轻量、按时间流动的记录呈现，不引入好友、公开可见性、评论或互动指标。

### 4.3 导航服从任务，不服从对称

目标信息架构由用户任务决定：

1. **记录**：快速写下此刻，选择心情、备忘、待办、打卡或附件。
2. **回顾**：按时间线、日历、相册、搜索与筛选重访记录。
3. **整理**：查看待办、标签、附件与收藏的内容集合。
4. **我的档案**：头像、封面、个人化展示与回顾摘要；若没有独立任务价值，不单独占用一级入口。
5. **设置与数据**：隐私、提醒、外观、导出／导入、存储占用与清理。

底部导航是否保留五项、具体叫什么名称，留待原型验证后决定。当前“自留地”和“自己”不能继续以重复时间线的方式长期共存。

## 5. 范围与阶段

### 当前原型（已具备或部分具备）

- 本地文字与图片动态记录；
- 时间线式浏览、相册浏览和关键词搜索；
- 头像、封面、主题、字体与每日提醒的基础设置；
- 本机文件中的记录与个人资料保存。

### P0：私密日记核心（下一阶段必须完成）

- 明确“自留地”是个人记录空间，不再暗示社交广场或公开内容；
- 统一记录模型，至少支持心情／日记、备忘录和图片附件；
- 一个清晰的“记录 → 保存 → 时间线回顾 → 搜索”闭环；
- 记录类型、日期、关键词的基础筛选；
- 本地数据状态、导出与删除路径可见且可验证；
- 移除或禁用无实际语义的“公开／谁可以看”表述；
- 对现有本地记录保持兼容，不因模型升级丢失内容。

### P1：个人生活整理能力

- 待办：创建、完成、逾期／今日视图、可选提醒；
- 打卡：自定义项目、每日记录、连续性回顾；
- 附件：图片、音频、视频、文档等本地文件的添加、预览、关联与删除；
- 日历、相册、标签和类型聚合视图；
- 应用锁或系统生物识别入口，并清楚说明保护边界。

### P2：仅在隐私方案成立后评估

- 加密导出、导入与迁移；
- 用户显式选择的加密备份／同步；
- 本地智能回顾、月度摘要或提醒建议；
- 小组件、快捷记录、跨设备恢复。

## 6. 关键用户旅程

### 6.1 写下一个情绪瞬间

用户打开应用，进入记录入口，写下文字、选择心情并可附加照片；保存后立即出现在私密时间线中。整个过程不要求选择受众，也不出现社交发布暗示。

### 6.2 将临时念头变成可完成的事

用户选择“待办”或从备忘录转换，填写事项和可选提醒。它既能在待办聚合视图中完成，也保留在当天时间线上，维持生活上下文。

### 6.3 回看某一天或某段记忆

用户从回顾进入日历、时间线、相册或搜索，按日期、关键词、类型或标签定位内容。图片、文字、打卡和待办可关联显示，但不会混淆为公开动态。

### 6.4 保存一个文件

用户从设备选择文件，应用显示类型、大小与保存位置，并允许将其独立保存或关联到一条记录。删除附件前必须说明对关联记录的影响。

## 7. 功能需求

### 7.1 记录与编辑

- 用户可以创建、编辑、删除和回看自己的记录。
- 每条记录至少拥有创建时间、类型、正文、附件列表和本地唯一标识。
- 心情、标签、提醒、完成状态等字段只在相应记录类型需要时出现。
- 记录保存失败时不得静默丢失用户输入；应给出可理解的恢复或重试路径。

### 7.2 回顾与检索

- 时间线必须展示所有记录类型，并可按类型筛选。
- 日记与备忘录支持关键词搜索；图片和文件至少可按日期与类型找到。
- 相册只展示可预览的媒体附件，不把文件附件误当作照片。
- “我的档案”若保留，展示的是个人资料与回顾入口，不复制完整内容流。

### 7.3 待办与打卡

- 待办支持未完成、已完成、可选日期／提醒，以及与某一日记或备忘的关联。
- 打卡支持用户自定义项目和按日记录；连续天数是回顾信息，不应制造强制打卡压力。
- 待办和打卡均必须能从统一时间线回到原始记录上下文。

### 7.4 文件与存储

- 附件只在用户主动选择后复制或持久化；应用应说明本地占用与删除影响。
- 首期优先支持图片，后续扩展音频、视频和文档；每增加一种文件类型都需定义预览、失败、导出和删除行为。
- 不因缓存清理、升级或记录删除而意外删除仍被其他记录引用的附件。

### 7.5 隐私与数据控制

- 默认数据范围：仅当前设备、当前用户。
- 导出、分享、导入、清空和未来备份必须是显式操作，并有二次确认与范围说明。
- 设置页必须能看见本地数据、存储占用、导出／导入状态和删除入口。
- 在未实现应用锁与加密前，界面不得使用“绝对安全”“已加密”等表述。

## 8. 非目标

- 不构建公开社区、好友关系、关注、评论、点赞或消息系统。
- 不将“朋友圈”做成社交平台的私有皮肤。
- 不在 P0 中承诺云同步、多用户协作、网页端、付费订阅或生产部署。
- 不因为底部导航视觉对称而新增无独立用户任务的页面。
- 不将任务管理、笔记或文件管理扩展为企业协作工具。

## 9. 验收标准

### P0 产品验收

- 用户能在三步内新建一条私密文字／心情记录，并在重启后仍可回看。
- 用户能添加图片附件，且它能在对应记录与相册／回顾中找到。
- 用户能创建备忘录，并通过关键词或时间找到它。
- 所有新建内容默认仅本地保存；审计正常使用流程时没有未经用户主动触发的内容外发。
- 任何“公开”“谁可以看”“朋友圈”等表达都与真实功能一致；未实现的社交或可见性能力不显示为可用。
- 导出、删除和清空行为能清楚说明影响范围；确认后结果可观察。
- 现有心情记录在升级后仍可读取，且迁移失败可恢复。

### 晋升为正式项目的证据

- 在真实 Android 设备上完成上述核心流程的行为验证；
- 明确数据模型、附件生命周期与隐私边界；
- 确定应用锁／加密／备份的最小可行方案及其未覆盖风险；
- 不再依赖仅为视觉对称存在的一级导航；
- 根据工作区治理流程确定正式承载项目或共享能力边界。

## 10. 风险与待决问题

1. 本机保存不等于设备遗失时仍然私密：应用锁、系统账户、文件权限和加密策略需要单独评估。
2. 多媒体与文档会迅速增加存储、预览、迁移和删除复杂度；必须先定义附件生命周期，再扩大格式支持。
3. 日记、备忘、待办和打卡共享时间线会提高回顾价值，也可能让首页过于复杂；需要用类型筛选和渐进式入口控制。
4. 是否需要跨设备同步尚未决定；在加密、冲突处理和恢复机制明确前，不应接入云端。
5. 底部导航最终形态、名称与“我的档案”是否单独保留，需以真实记录与回顾使用情况验证，而不是以视觉平衡决定。

## 11. 成功信号

- 用户愿意连续一周把日常心情、临时念头或待办留在 Axi Mood 中；
- 任意一条记录能在需要时被快速找到，而不是只被写下后遗忘；
- 用户能清楚说出“内容只属于我、保存在何处、如何导出或删除”；
- 产品首页和一级导航的每个入口都对应不同的真实任务。
